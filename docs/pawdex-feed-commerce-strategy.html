PawDex 재정리: 사료 커머스 중심

AI 건강기록으로 맞춤 사료를 추천하고, 최저가 구매와 병원 문서 보관까지 연결

이번 방향의 메인은 로얄캐닌 사료 판매입니다. PawDex의 기존 강점인 반려동물 건강기록과 AI 분석을 활용해 아이 상태에 맞는 사료를 추천하고, 보호자는 바로 구매하거나 정기배송을 설정합니다. 병원 연계는 사료 추천의 신뢰와 건강기록의 이동성을 높이는 보조 인프라로 가져가는 것이 좋습니다.

제품 포지션 AI 사료 추천 병원찾기 UI 병원 문서/예약 문서함 UX 비계약 병원 대응 커머스/정산 사용자별 화면 우선순위

1. 제품 포지션을 다시 잡으면

PawDex는 “동물병원 플랫폼”으로 시작하기보다 “기록 기반 맞춤 사료 커머스”로 시작하는 편이 더 선명합니다. 병원 기능은 처음부터 크게 만들 필요는 없고, 사료 추천을 더 믿게 만들고 보호자 기록을 더 쓸모 있게 만드는 기능부터 붙이면 됩니다.

메인 매출

로얄캐닌 사료 판매

  • 총판 연결로 가격 경쟁력 확보
  • 일반 구매 + 정기배송
  • 아이 상태별 추천 상품 노출
차별점

기록 기반 추천

  • 품종, 나이, 체중, 중성화 여부
  • 증상/진료/복약/입퇴원 기록
  • AI 분석 결과와 보호자 관심사
신뢰 장치

병원 문서 보관

  • 검사결과, 진단서, 처방 안내 보관
  • 응급 시 다른 병원에 즉시 보여주기
  • 사료 추천 근거로 활용 가능
한 줄 전략: “싸게 파는 사료몰”이 아니라 “우리 아이 기록을 보고 필요한 사료를 골라주는 사료몰”로 가야 합니다.

2. AI 사료 추천 흐름

로얄캐닌은 강아지/고양이의 나이, 품종, 크기, 생활단계, 건강관리 목적에 따라 제품군이 다양합니다. 이 다양성이 PawDex의 기록/AI 기능과 잘 맞습니다. 다만 질병 치료를 단정하면 안 되고, “추천 근거 + 수의사 상담 필요 표시”가 같이 있어야 합니다.

1

아이 프로필

종, 품종, 나이, 체중, 중성화, 활동량, 알러지, 만성질환을 입력합니다.

2

기록 분석

증상, 진료, 입퇴원, 복약, 체중 변화, 검사결과를 AI가 요약합니다.

3

사료 후보

일반식, 기능성, 처방식 후보를 분리해서 추천합니다.

4

주의 표시

처방식/질환 관련 제품은 수의사 상담 또는 병원 확인이 필요하다고 표시합니다.

5

구매/정기배송

용량, 급여량, 예상 소진일을 계산해 바로 구매 또는 정기배송으로 연결합니다.

6

피드백 학습

기호성, 변 상태, 알러지 반응, 체중 변화를 기록해 다음 추천에 반영합니다.

추천 화면 구성

보호자에게 이렇게 보여주기

  • 1순위 추천 사료: “현재 기록 기준 가장 적합”
  • 대체 후보: 가격/기호성/용량 기준 비교
  • 추천 근거: 나이, 체중, 증상 기록, 진료 기록 기반
  • 주의 문구: 질환 관리/처방식은 수의사 상담 권장
  • 급여 계산기: 하루 급여량, 한 포대 예상 사용일
금지해야 할 표현

법적/신뢰 리스크 줄이기

  • “이 사료가 치료합니다” 같은 치료 단정
  • 검사결과 없이 특정 질병 처방식 확정 추천
  • 수의사 진료를 대체한다는 표현
  • AI가 진단했다는 표현

3. 병원찾기 화면 확장안

이미 병원찾기 기능이 있으므로, 완전히 새 기능을 붙이기보다 현재 지도 화면을 “탐색 + 병원 액션 패널”로 확장하는 편이 좋습니다. 지도는 화면의 약 2/3, 아래는 선택한 병원의 예약/문서/공유 액션 패널로 두면 보호자가 바로 행동할 수 있습니다.

화면 구조

지도 2/3 + 하단 패널 1/3

  • 상단 2/3: 지도, 병원 마커, 내 위치, 검색 결과
  • 하단 1/3: 선택 병원 카드, 액션 버튼, 제휴 배지
  • 병원 카드를 위로 올리면 상세 정보 전체 보기
  • 계약 병원은 예약/문서수신/기록공유 버튼 노출
  • 비계약 병원은 전화/길찾기/내보내기 중심으로 노출
제휴 병원 표시

홍보와 기능을 같이 제공

  • 지도 마커 색상 또는 아이콘을 다르게 표시
  • “PawDex 제휴 병원” 배지 노출
  • 리스트에서 우선 노출 또는 필터 제공
  • “앱 예약 가능”, “검사결과 앱 수신”, “기록 공유 가능” 배지
  • 병원 상세에 소개, 전문 진료, 담당 수의사, 이벤트 표시
하단 액션 계약 병원 비계약 병원 제품 가치
예약 요청 날짜/시간, 담당 수의사, 진료 목적 선택 후 앱 예약 전화 버튼 또는 병원 외부 예약 링크 지도에서 바로 행동하게 만들어 전환율 상승
기록 공유 보호자가 선택한 반려동물 기록을 병원 웹에서 열람 24시간 임시 링크/QR/PDF 내보내기 초진/응급 상황에서 설명 시간을 줄임
문서함 병원이 보낸 검사결과, 진단서, 처방 안내 수신 보호자가 직접 파일 업로드 또는 이메일 파일 저장 메일보다 찾기 쉽고 반려동물별로 정리됨

응급 공유 카드 병원 웹에서 더 자세히 볼 수 있음 보호자 QR/링크로 최근 기록만 열람 계약 병원이 없어도 앱을 계속 쓸 이유가 생김
판단: 제휴 병원을 따로 표시하는 것은 좋습니다. 단순 광고가 아니라 “PawDex로 예약/문서수신/기록공유가 가능한 병원”이라는 기능형 홍보라 병원에도 설득력이 있습니다.

4. 병원 기능은 “문서 전달 + 기록 이동성”부터

검사결과를 메일로 받는 현재 방식은 보호자가 다시 찾기 어렵고, 다른 병원에 급히 갈 때 바로 보여주기 불편합니다. 앱으로 받으면 반려동물별 건강기록에 자동 정리되고, 응급 상황에서 바로 공유할 수 있다는 강점이 생깁니다.

병원 1개부터 시작해도 됩니다. 오히려 처음에는 A 병원 한 곳과 깊게 붙어서 “문서 보내기, 예약, 보호자 앱 수신”을 제대로 검증하는 편이 좋습니다. 병원 여러 곳을 먼저 늘리면 운영, 교육, CS, 권한 관리가 한꺼번에 커집니다.
병원별 문서함

받은 파일 목록 구조

  • 보호자 앱에 “병원 문서함” 메뉴 생성
  • 병원명 목록 표시: 예) A동물병원, B동물메디컬센터
  • 병원 클릭 시 날짜별 받은 파일 타임라인 표시
  • 파일 유형: 검사결과, 진단서, 소견서, 처방 안내, 수술 후 주의사항
  • 각 파일은 해당 반려동물의 건강기록에도 연결
메일 수신 대체

왜 앱 수신이 더 좋은가

  • 메일함에서 파일을 다시 찾는 불편이 줄어듦
  • 반려동물/병원/날짜별로 자동 정리됨
  • 응급 시 다른 병원에 바로 보여줄 수 있음
  • 병원은 재발송 문의와 보호자 안내 비용이 줄어듦
  • 사료 추천 시 검사결과/진료기록을 참고할 수 있음

5. 문서함과 기록 첨부 UX

병원에서 받은 서류와 보호자가 직접 첨부한 파일은 성격이 다릅니다. UX적으로는 “문서함은 원본 보관소, 건강기록 첨부는 특정 기록에 연결된 파일”로 분리하는 것이 가장 깔끔합니다. 파일을 여러 곳에 복사 저장하지 않고, 원본 문서 하나를 필요한 기록에 연결하는 구조가 좋습니다.

문서함

원본 보관소

  • 병원에서 받은 검사결과, 진단서, 소견서, 처방 안내를 보관
  • 병원별 목록으로 정리
  • 병원 클릭 시 날짜별 문서 타임라인 표시
  • 파일 유형, 발급일, 담당 수의사, 연결된 반려동물 표시
  • 내보내기, 공유, QR, 다운로드의 기준 위치
건강기록 첨부

기록 맥락

  • 보호자가 직접 올린 사진/PDF는 기존 첨부파일로 유지
  • 병원에서 받은 문서는 “연결된 병원 문서”로 별도 표시
  • 기록 상세에서 문서를 열면 문서함 원본을 보여줌
  • 한 문서를 여러 기록에 연결할 수 있음
  • 원본 삭제/권한 변경은 문서함에서 관리

병원 전송

“A병원에서 새 문서가 도착했어요” 알림을 띄웁니다.

3

문서함 저장

문서는 병원별/날짜별 문서함에 원본으로 저장됩니다.

4

기록 연결 제안

새 진료기록 만들기, 기존 기록에 연결하기, 나중에 하기를 제안합니다.

5

기록에서 표시

기록 상세에는 “연결된 병원 문서” 섹션으로 보입니다.

6

내보내기

문서함에서 개별 문서 또는 응급 패키지로 공유합니다.

위치 보여줄 내용 주요 액션 UX 원칙
마이페이지 보관함 전체 문서, 저장한 분석, 받은 병원 문서 검색, 필터, 다운로드, 삭제/숨김 전체 파일을 관리하는 보관소
병원 탭 받은 문서 병원별 받은 문서 목록 병원별 보기, 날짜별 보기, 병원 상세 이동 병원 맥락에서 빠르게 찾기

  • 최근 검사결과와 진단서
  • 보호자 연락처와 반려동물 기본 정보
  • 24시간 링크 또는 PDF 묶음
추천 UX: 마이페이지 보관함은 전체 관리용으로 유지하되, 병원 문서는 병원 탭과 홈 알림에서도 접근할 수 있게 해야 합니다. 저장 위치는 하나지만 들어가는 길은 여러 개가 되는 구조가 가장 편합니다.

6. 계약 병원만 가능하게 할까, 비계약 병원도 볼 수 있게 할까?

둘 다 필요합니다. 계약 병원은 병원 프로그램에서 바로 보내고 받는 “깊은 연동”을 제공하고, 비계약 병원에는 보호자가 직접 보여줄 수 있는 “내보내기/공유 링크”를 제공해야 앱의 실제 가치가 커집니다.

계약 병원

병원용 프로그램/웹 제공

  • 보호자 검색 또는 QR로 연결
  • 검사결과/진단서/주의사항 전송
  • 담당 수의사 예약 슬롯 관리
  • 보호자가 동의한 기록 열람
  • 병원 추천 사료 또는 식이 관리 안내
비계약 병원

보호자 주도 내보내기

  • 응급 공유 링크: 24시간 후 만료
  • QR 코드로 최근 기록/검사결과 보기
  • PDF 내보내기: 보호자 소유 기록 묶음
  • 열람 로그: 언제 누가 봤는지 보호자 확인
  • 공유 철회: 링크 즉시 비활성화
추천 구조: 계약 병원은 “쓰기 권한”을 주고, 비계약 병원은 “보호자가 만든 임시 읽기 권한”만 줍니다. 이렇게 하면 병원 영업이 아직 안 된 지역에서도 보호자가 앱을 계속 쓸 이유가 생깁니다.

7. 판매자 센터, 구매자 쇼핑, 정산 구조

사료가 메인이면 커머스 뼈대가 반드시 먼저 필요합니다. 현재 Toss 빌링 흐름이 있으므로 정기배송은 강점이 될 수 있고, 단건 결제 심사가 끝나면 일반 구매까지 확장하면 됩니다.

권장 포지셔닝

“AI가 진단해서 사료를 처방합니다”가 아니라 “PawDex가 기록을 정리해 우리 아이에게 맞는 사료 후보를 추천하고, 필요한 경우 수의사 상담을 연결합니다”가 더 안전합니다.

9. 추천 개발 우선순위

지금은 사료 매출을 먼저 검증해야 합니다. 병원 연계는 A 병원 하나로 시작해서 문서 전송/예약만 검증하고, 비계약 병원 대응은 보호자 내보내기 기능으로 해결하는 것이 현실적입니다.

1순위

로얄캐닌 상품 카탈로그 + 구매자 쇼핑

상품, 옵션, 가격, 재고, 상세 페이지, 장바구니, 주문내역부터 만듭니다. 판매자 센터는 총판 1곳 전용으로 작게 시작합니다.

2순위

AI 사료 추천 엔진

기존 반려동물 프로필/건강기록/AI 분석을 상품 태그와 연결합니다. 추천은 카탈로그 안에서만 하도록 제한합니다.

3순위

정기배송/빌링 확장

이미 구현된 Toss 빌링 흐름을 사료 정기배송에 연결합니다. 사료는 반복 구매 품목이라 구독과 궁합이 좋습니다.

4순위

병원찾기 하단 액션 패널

지도는 2/3로 줄이고, 아래에 선택 병원의 예약/전화/길찾기/기록공유/문서함 액션을 붙입니다. 제휴 병원 배지도 함께 노출합니다.

5순위

A 병원 문서 전송 MVP

계약 병원 1곳에 병원 웹을 제공하고, 검사결과/진단서/주의사항을 보호자 앱으로 보내는 흐름을 검증합니다.

6순위

비계약 병원용 내보내기/응급 공유

24시간 링크, QR, PDF 내보내기를 제공해 계약 병원이 아니어도 보호자가 기록을 보여줄 수 있게 합니다.

7순위

예약/담당 수의사/응급 콜

문서 전송이 실제로 쓰이는 병원이 생긴 뒤 예약과 응급 콜을 붙입니다. 운영 부담이 크므로 후순위가 맞습니다.

메인: 로얄캐닌 맞춤 추천 + 구매 반복 매출: 정기배송 신뢰: 건강기록/검사결과 보관 확장: 병원 문서 전송/예약 방어력: 비계약 병원 내보내기
